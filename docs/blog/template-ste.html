In September 2026, Jev made decision models popular. A decision model does not write text. It gives a probability for each permitted answer to a question. Jev reads only text. Two weeks later, Cloudflare released Clef. Clef uses the same method, and it also reads images. Few people know about Clef. We tested it on documents.

  • Jev, now with vision support. Clef is an open model from Cloudflare. It answers Jev-style questions about an image. It gives a probability for each answer, and it does not write text.

What is Clef?

This section is an introduction. It describes decision models, and it shows what Clef adds.

Most AI models in use today are generative models. You ask a question, and the model writes an answer. This is good for a conversation. But much routine work is not a conversation. Some questions need only a short decision: is this an invoice? or is this total correct? For these questions, a written answer is slow and expensive. Its format can change. Also, it does not show how sure the model is.

Decision models use a different method. You send an input and a set of questions. Each question has a fixed set of answers. The model gives a probability for each answer, for example for invoice, receipt and letter. The model does not write text. In September 2026, Jev made this method popular. But Jev reads only text.

On 1 October 2026, Cloudflare released Clef. Clef uses the same question types and the same requests as Jev. Its weights are open. There are two sizes: Clef-flash (9 billion parameters) and Clef (27 billion parameters). Clef also reads images. Cloudflare gives results for more than forty benchmarks. All of these benchmarks use only text. No benchmark uses a document. No result shows if the probabilities are reliable.

What can a decision model do when it can see?

This section gives applications. Each application is a decision that uses the content of a page or an image.

Work with documents includes many small decisions. There are two types. Some decisions are about the document: what is this page, and is it complete? Other decisions are about the content: what does the page say, and is the extracted value correct? A decision model with vision changes each decision into one question about the page:

The same method applies to other images. Examples: is this screenshot an error screen? Does this product photo agree with the product description? Does this identity document show the photo page? We did not test these.

Why not use OCR and send the text to Jev?

Jev is available, so this is a good question. For many of these decisions, text is not sufficient.

  • OCR keeps the words and loses other data. OCR can lose the layout, ticks, stamps, signatures, handwriting and the column of a number.
  • OCR errors become facts for the model. Sometimes OCR reads 30.000 as 30.900. Then a text model compares one OCR result with another OCR result. Only a model with vision can compare the value with the page.
  • Two systems, not one. You must operate, adjust and pay for the OCR tool and for the text model. Their errors add together.

Thus, the important question is this: can a decision model with vision read documents sufficiently well for these decisions? We did tests to find the answer.

We used Clef-flash and Clef 27B in each test. We asked each question two times: one time as a multiple choice and one time as a yes or no question. The incorrect answers were always realistic. For receipts, they were the other amounts on the same receipt. We also used the true total with one digit changed. For business pages, the incorrect answers were text from the same page. Part 1 · Questions about the content

Can Clef read the content of the page?

This is the content test. The results of the two models were better than we expected.

For receipts, Clef-flash selected the correct total in __CORD_RIGHT__ of __CORD_CHOICE_N__ questions. For business pages, it gave the correct answer to __DOC_RIGHT__ of __DOC_N__ multiple-choice questions. Clef 27B also got __DOC_BIG_ACC__%. The type of content on the page had almost no effect:

Business pages: the percentage of all questions (multiple choice and yes or no) with a correct answer, by the skill that the question needs.

The yes or no questions are more difficult, because the incorrect value can be almost correct. One receipt shows the total __NEAR_TRUE__. We asked Clef-flash if the total is __NEAR_ASKED__. It said no, with __NEAR_NO__% confidence. On all __CORD_N__ receipts, Clef-flash accepted a changed digit only __FOOLED_FLASH__ time. Also, its confidence agreed with its results: answers with very high confidence were almost always correct. Thus, a machine can do the sure cases, and a person can do the other cases.

Is the larger model safer?

This section compares Clef 27B with Clef-flash. In the most difficult receipt test, Clef 27B was less safe.

Clef 27B selected the correct receipt total in __BIG_CORD_ACC__% of the questions. This is slightly better than Clef-flash. Then we did the one-digit test:

Clef 27B accepted __FOOLED_BIG__ incorrect totals of __FOOLED_N__. Clef-flash accepted __FOOLED_FLASH__. Almost all the errors of Clef 27B were near misses: the incorrect total was within a few percent of the true total. Clef-flash examines each digit. Clef 27B accepts a value that is approximately correct. On business pages, the incorrect answers were different text, not near-miss numbers. There, the two models had the same result. The few errors of Clef 27B were of the opposite type: it said no to __BIG_NO_TRUE__ correct answers.

To examine extracted values is a frequent task in document work. For this task, the smaller model was the safer model, and it is also faster and cheaper. The numbers are small. Thus, this result is a strong indication, not a proof.

Part 2 · The doubt

Is __DOC_ACC__% too good to be correct?

This is a contamination test of the content results. Clef reads the page. It does not use memory.

We must examine results that are this high. The three test sets are public, and they have been on the internet for many years. Thus, the model possibly saw these pages during its training. If this is true, the model can use memory, not the page.

We asked Clef-flash the same __CONTAM_CALLS__ questions again. We changed only the image. One time, we sent a blank page of the same size. One time, we sent a different document from the same set. If the model reads the page, its results must decrease. If the model uses memory, its results must stay high.

Clef-flash: the same questions with the real page, a blank page and a different page. The dotted lines show the random result for the multiple-choice questions.

The best test is the yes or no question with the true value, because the question does not show the answer. With the real receipt, Clef-flash said yes in __CR_REAL__% of the questions. With a blank page, it said yes in __CR_BLANK__%. With a different receipt, it said yes in __CR_SWAP__%. The business pages gave the same result: __CD_REAL__%, then __CD_BLANK__% and __CD_SWAP__%. Clef reads the page.

For receipts, without the real page, the multiple-choice result decreased to __CRC_BLANK__% and __CRC_SWAP__%. A random selection gives __CRC_CHANCE__%. For business pages, the result was __CDC_BLANK__% with a blank page and __CDC_SWAP__% with a different page. A random selection gives __CDC_CHANCE__%. This is not memory. Some of our questions show the answer: which room, smoking or non-smoking? had only one option that is a type of room. The corrected dinner time had only one evening time. Without the page, the model was correct on __LEAK_WORDS__ answers that are words, but only on __LEAK_NUMS__ answers that are numbers. Thus, the multiple-choice result for business pages is slightly too high. The yes or no results are correct.

Part 3 · Questions about the document

Can Clef identify the page type?

This is the document test. The result was low at first. Then we examined the labels.

Clef-flash identified the page type correctly in __E01_ACC__% of the pages. Clef 27B got __E02_ACC__%. Then we examined the pages with an incorrect answer from Clef-flash:

  • One page has the label letter. Its heading, in large letters, is Interoffice Memorandum. The model said memo.
  • One page has the label resume. The page has only one word: APPENDIX. The model said blank or unreadable.
  • One page has the label handwritten. It is a handwritten research report. The model said scientific report. Both answers are correct.

A different reviewer examined each page with an incorrect answer. The reviewer did not see the answer of the model. There were __MISSES__ incorrect answers. In __LABEL_PROBLEMS__ of them, the label had a problem. __LBL_WRONG__ labels were incorrect. In __LBL_NOTVIS__ pages, the label was not visible on the page. __LBL_AMBIG__ pages had two correct answers.

Page-type answers of Clef-flash on __E01_PAGES__ pages, in groups by confidence. “Fits the page” means that the reviewer found the answer of the model correct for the page.

The model gave __HIGH_N__ answers with a confidence of 70% or more. Of these answers, __HIGH_WRONG__ were really incorrect. All the really incorrect answers had low confidence. With the examined labels, the result increases to __E01_CHECKED__%. If each answer that fits the page is correct, the result is __E01_FITS__%. The page type is more difficult than a value on the page. But here also, the confidence shows which answers you can use.

What problems did we find?

This section gives practical information for other users.

  • Large images are not accepted. The service calculates the size of an image from its encoded text. It does not accept images larger than approximately 185 KB. We decreased the pages to 1,024 pixels on the long side.
  • The “confidence” field is not the probability of the answer. The confidence field of the hosted API shows how much the probabilities are in one answer. Use the probabilities to set thresholds.
  • Test sets also have errors. Old datasets have incorrect labels. Our tool also gave “6-2-97” and “June 2, 1997” as two different answers. Examine the errors before you use a result.

What will we do next?

Each item comes from a result of this test.

  • More difficult content. Line items, counts, and a check that the numbers on a page add up.
  • Real invoices. Business documents that are not well-known public test sets.
  • Better incorrect options. Incorrect answers of the same type as the correct answer, so that the question does not show the answer.
  • Approximately correct values. More near-miss values, to find if the problem of Clef 27B continues.

Notes on the method

We used the two models in all three tests. We did the contamination test only with Clef-flash. The samples are small: __E01_PAGES__ to __DOC_PAGES__ documents in each test. The models are hosted, and we cannot select a fixed model version. We decreased the size of the images. We did not use pages that were too large after this. An AI tool helped with the label review for page types. It did not see the answers of the model. A person must still do a final review. The script docs/blog/build.py makes all numbers and charts on this page from the saved replies. The raw replies, the research journal and all scripts are in the doc-jev repository.
